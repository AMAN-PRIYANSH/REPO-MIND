- Recommended model: **Opus 5.5**, effort **high**
- Branch: this session's own `claude/...` branch (see `CLAUDE.md` section 5)
- Target duration: 3-4 days of builder work, then an adjudication round (supervisor and owner), then a short scoring session
- Required reading: `CLAUDE.md`, `docs/progress/STATUS.md`, `CP7.md`, `CP7b.md`, `CP9.md` (**review notes at the end of each bind this checkpoint**), `docs/results/CP7B_REAL_APPS_RESULTS.md`, `docs/results/CP9_FEASIBILITY_RESULTS.md`, `docs/results/cp7b/adjudication_reviews/`, `docs/results/cp9/d3b/adjudication_reviews/`, `src/vulntrace/pipeline/symbols.py`, `src/vulntrace/d3/govuln.py`

## Goal

Answer the question an interviewer or a security team asks: **is the verdict right, and is it at least as good as govulncheck where govulncheck can answer, and more useful where it cannot?**

Until now real-application results measured the **shown path** (CP7b, CP9: 0/7 runnable). This checkpoint measures the **verdict** (is any target reachable from `main` by some route), improves it where a clear cause is known, and makes the evidence say how sure it is.

## Findings that shape this checkpoint

- On D3 (CP7b), our two false alarms where govulncheck said NOT_REACHABLE were driven by targets the fix did not change (`context_only`) or by a branch selected by constants; govulncheck uses the curated vulndb symbol list.
- D3 and D3b were selected from advisories **with** curated symbols, where govulncheck works at symbol level. The case VulnTrace was designed for (advisories **without** curated symbols, where govulncheck can only say "package imported") has never been measured on real applications.
- Path precision is near 0 on real applications; F1-F3 do not generalise (CP9). Evidence must therefore show its own uncertainty rather than claim a runnable path.

## Deliverables

1. **Target hygiene (Mode 1), rules fixed in code before any new data is run**
   - If the advisory has curated vulndb symbols for the module: those symbols are the decision targets (`origin: VULNDB`); changed functions from the fix commit are kept as extra evidence only.
   - If it has none: decision targets are the changed non-test functions, **excluding `context_only` ones**. If only `context_only` targets are reachable, the verdict is `CANT_DETERMINE` with reason `ONLY_CONTEXT_TARGETS_REACHABLE` (never `NOT_REACHABLE`).
   - A `--legacy-targets` switch reproduces CP7/CP9 verdicts exactly (test).
   - Hygiene can turn a REACHABLE into NOT_REACHABLE only in the curated-symbol stratum, where both methods find none of the curated symbols. Every such change is listed and adjudicated.

2. **Evidence honesty**
   - Path ranking among the examined paths (the CP9 search, N recorded): prefer paths that pass the CP9 filter, then fewer `DYNAMIC` steps, then shorter.
   - Each `DYNAMIC` step carries `confirmed: false` and the kind (interface method, function value, closure through a parameter). A verdict records `evidence_level`: `STATIC_PATH` (no dynamic step) or `HAS_DYNAMIC_STEPS` (with their count).
   - The demo page and the text output say plainly "route shown is an example from the call graph; steps marked unconfirmed may not run in this context".

3. **New held-out set D3c (the evidence for this checkpoint)**
   - 4 new real applications chosen by the existing D3 selection code with its written rules, **excluding the 8 D3/D3b applications**, a new seed recorded before any run, and **two strata with quotas**: at least 8 cases whose advisory has curated vulndb symbols (stratum S) and at least 8 whose advisory has a fix commit but no curated symbols (stratum N). If stratum N cannot be filled from 4 applications, add applications by the same rules and say so.
   - Run VulnTrace (new rules and `--legacy-targets`) and govulncheck (source mode, symbol scan, pinned vulndb, nothing of the application executed) on every case.

4. **Verdict-level adjudication sheets** (same format family as CP7b/CP9)
   - D3c: **every case** (all verdicts): `truth` (any decision target reachable from a `main` package by some route? `REACHABLE` / `NOT_REACHABLE` / `UNKNOWN`), plus, for REACHABLE verdicts, the shown path's judgement (`CORRECT` / `INFEASIBLE_PATH` / `WRONG` / `CANNOT_JUDGE`).
   - Truth-only items for the earlier sets where truth is missing: the 7 D3 REACHABLE cases and the D3b cases that were not REACHABLE.
   - The builder prepares the sheets and stops at `AWAITING_ADJUDICATION`; the supervisor runs the CP7b method (two independent reviewer agents, reconciliation, owner spot-check).

5. **Scoring** (second short session) - `docs/results/CP10_VERDICT_RESULTS.md`, rendered by code, headline sentence fixed in the renderer before any D3c result exists. Per stratum (S, N) and overall, for VulnTrace (new and legacy) and govulncheck:
   - verdict precision of REACHABLE (truth REACHABLE among REACHABLE verdicts), false NOT_REACHABLE count (truth REACHABLE but verdict NOT_REACHABLE: the dangerous error), CANT_DETERMINE rate, UNKNOWN truth count, with 95% intervals and n.
   - govulncheck's answer at its own level (symbol, package, module); in stratum N a package- or module-level finding is scored as its REACHABLE claim, and this is stated.
   - Paired comparison VulnTrace vs govulncheck on the same cases (agree / disagree, who was right per adjudication).
   - Path precision split by `evidence_level`.
   - D3 and D3b verdict-level results reported separately and labelled in-sample.

6. **Tests:** hygiene rules, legacy reproduction, ranking and labels, sheet generation and scoring; CI green.

## Out of scope

New F-patterns or symbolic execution, LLMs in the verdict path, changing VTA or the two-method rule, retrieval changes, Mode 2 changes, tuning anything on D3c results.

## Known risks

- Stratum N may be hard to fill (few applications pull a vulnerable version of a module whose advisory lacks symbols). Report how many candidates were tried.
- govulncheck at package level in stratum N will look "more cautious"; that is not a win for either tool by itself. Score only against adjudicated truth.
- n stays small; say "no detectable difference" when intervals overlap.
