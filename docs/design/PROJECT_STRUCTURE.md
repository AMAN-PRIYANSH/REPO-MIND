# Planned project structure

This is the planned layout. None of the code directories exist yet. Each checkpoint creates only the parts listed for it.

```
REPO-MIND/
├── README.md
├── CLAUDE.md                          # rules every Claude Code session reads
├── pyproject.toml                     # CP1; optional dependency groups: [models], [agent], [db], [demo]
├── .gitignore                         # CP1
├── docker-compose.yml                 # CP4: PostgreSQL + pgvector for real runs
├── docs/
│   ├── progress/STATUS.md             # checkpoint ledger and handoff notes
│   ├── progress/reports/              # one report per checkpoint
│   ├── implementation/checkpoints/    # CP1.md ... CP8.md (written one at a time)
│   └── results/                       # committed result summaries, generated by code
├── prompts/
│   ├── SESSION_WRAPPER.md             # pasted at the start of every Claude Code session
│   └── templates/                     # CP5+: versioned LLM prompt templates
├── schemas/                           # JSON Schemas, source of truth for data shapes
├── src/vulntrace/
│   ├── __main__.py                    # CP1: CLI
│   ├── env.py                         # CP1: doctor
│   ├── schemas.py                     # CP1: validation helpers
│   ├── methods/linker.py              # CP1
│   ├── methods/callgraph.py           # CP2: Go helper wrapper
│   ├── methods/naive.py               # CP2: negative control
│   ├── verdict.py                     # CP2
│   ├── dataset/                       # CP3: vulndb reader, fix evidence, release ranges, baselines
│   ├── models/                        # CP4-CP5: LLMClient, Embedder, Reranker interfaces + fakes + real impls
│   ├── retrieval/                     # CP4: chunking, BM25, dense, RRF, rerank, HyDE, vector stores
│   ├── selection/                     # CP5: closed-set LLM selection, validation, cache
│   ├── agent/                         # CP6: LangGraph graph, tools, budgets, traces
│   ├── lift.py                        # CP5
│   ├── verify.py                      # CP7
│   ├── pipeline.py                    # CP7: triage, both modes
│   ├── demo/                          # CP7: small Streamlit page
│   └── eval/                          # CP1+: metrics and report writers
├── helper/                            # CP2: Go module for vt-helper (funcs, reach, edges, lift)
├── fixtures/reachability/             # CP1: synthetic Go cases + manifest.json
├── notebooks/                         # CP4+: Colab notebooks for real model runs
├── tests/
│   ├── unit/                          # CP1+
│   ├── contract/                      # CP2+: recorded helper and model responses vs schemas
│   └── integration/                   # CP1+ (skips with a clear reason if a tool is missing)
├── data/                              # generated case files (gitignored except small samples)
└── results/                           # gitignored raw run outputs
```

## Rules

- Python 3.11+, `src/` layout. Base dependencies stay small; model, agent, database and demo libraries go in optional groups so tests run without them.
- `helper/` and `fixtures/` are separate Go modules; fixtures have no external dependencies and build with `GOPROXY=off`.
- Notebooks only call project code (`pip install` of this repository plus the optional groups). Logic never lives only in a notebook.
- Large or regenerable data, model files and embeddings are never committed. Small, reviewed result summaries and cached model outputs needed to reproduce headline numbers are committed under `docs/results/` (size limits set in CP4).
- golang/vulndb content is referenced by commit SHA, not copied, until its licence terms are checked (open question).
