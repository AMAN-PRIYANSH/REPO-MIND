## Mismatches and inlining flips, explained

The case list is computed from the data; the explanation text is hand-written (`docs/results/notes/cp1_linker.json`) from reading the fixture code.

- `inlined_small`: Flips to ABSENT with inlining enabled. `ParseTiny` is a one-line function; the compiler inlines it into main and the linker then drops the unused out-of-line copy. This is why scoring uses only the `-gcflags=all=-l` run (ADR-013).
- `method_value_receiver`: Flips to ABSENT with inlining enabled. The target `Impl.Run` is a one-line method; when it is inlined at its only (static) call site and no interface or reflection use keeps it, the linker drops the method symbol. Explanation inferred from the code; the binary was not disassembled.
- `method_pointer_receiver`: Flips to ABSENT with inlining enabled, for the same reason as `method_value_receiver` (one-line `(*PImpl).Run`, static call only). Explanation inferred from the code; the binary was not disassembled.

## Other observations (hand-written)

- `generic_target`: PRESENT, by a prefix-match rule added in CP3 task 0c. The target is written as the generic form `ParseAny[T]`; building this fixture with several instantiations (`string`, `int`, `[]byte`) showed each produces a *different*, shape-specific binary symbol (`ParseAny[go.shape.string]` etc.), never the concrete type vulndb would name, so no rule can match one specific instantiation. The bracket does reliably start right after the function's own name for a bare generic function (never after a dot), so a prefix match `pkg.ParseAny[` answers 'is any instantiation present', which is all the linker method needs. A generic *method*, or a method on a generic type, embeds the type argument inside the receiver's own brackets instead (e.g. `pkg.(*List[go.shape.string]).Push`) and still has no rule: it stays ERROR with UNSUPPORTED_SYMBOL_FORM.
- `unsafe_func_pointer`: Not a real test of `unsafe`. The program takes the function value `vulnlib.Parse` before converting it through `unsafe.Pointer`, and taking a function value keeps the symbol in the binary, so the result says nothing about `unsafe`-hidden calls (CP1 review note).
- `build_tag_excluded`: Trivial agreement: the excluded file is never compiled, so no method can see the call.
- `test_file_only`: Trivial agreement: `_test.go` files are not part of the built program.
