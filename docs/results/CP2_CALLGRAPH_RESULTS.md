## Disagreements and mismatches, explained

The case list and the per-method outcomes are computed from the data; the explanation text is hand-written (`docs/results/notes/cp2_callgraph.json`) from reading the fixture code and the observed paths.

- `func_value_map` (R1 FALSE_NOT_REACHABLE; R2 AGREE; R3 AGREE; R4 REACHABLE): R1 misses the call because `h("a b")` calls a function value taken from a map; the naive graph only follows calls written by name. VTA tracks the value `vulnlib.Parse` into the map and out to `h`, and reports a DYNAMIC edge main -> Parse. This is the failure that motivated ADR-002/004.
- `reflect_method` (R1 FALSE_NOT_REACHABLE; R2 AGREE; R3 FALSE_NOT_REACHABLE; R4 CANT_DETERMINE (METHOD_DISAGREEMENT)): The disagreement the CP2 spec predicts. VTA reports NO_PATH: the call goes through `reflect.Value.Call` on a method found by a run-time name, and x/tools documents VTA as sound only 'modulo use of reflection and unsafe' (go/callgraph/vta/vta.go). The linker keeps `Impl.Run` and therefore `Parse`: once a reflect method lookup is reachable, the linker's dead-code pass (`reflectSeen` in cmd/link/internal/ld/deadcode.go) keeps exported methods of reachable types. NO_PATH + PRESENT gives CANT_DETERMINE / METHOD_DISAGREEMENT. VTA alone would have been a false NOT_REACHABLE; this is why the rule needs the second method. R1 also misses it (no call written by name).
- `interface_not_instantiated` (R1 FALSE_REACHABLE; R2 AGREE; R3 AGREE; R4 NOT_REACHABLE): R1 is a false REACHABLE: the naive graph links the interface call `r.Run` to every method named `Run` in the analysed packages, including `worker.Run`, which no value ever reaches. VTA sees that only `quiet{}` flows to `r`.
- `method_value` (R1 FALSE_NOT_REACHABLE; R2 AGREE; R3 AGREE; R4 REACHABLE): R1 misses the call: `f := vulnlib.Impl{}.Run; f("a b")` calls a method value, not a name. VTA follows it through the bound-method wrapper `Impl.Run$bound`.
- `build_tag_excluded` (R1 ERROR; R2 AGREE; R3 AGREE; R4 NOT_REACHABLE): `vtfixtures/vulnlib` is imported only by `tagged.go`, which the default build excludes, so the package is not in the loaded program. Naive still returns TARGET_NOT_FOUND for it (R1 is unchanged by the CP3 task 0a contract change: it keeps the original rule, 'package not parsed' is still an error for the unsafe negative control). VTA now applies the interfaces-contract exception added after the CP2 review (implemented in CP3 task 0a): a target whose package is not part of the loaded program at all reports NO_PATH with `details.package_not_in_program = true`, instead of TARGET_NOT_FOUND, because no code from an unimported package can run. Linker reports ABSENT (the symbol was never referenced, so it was never linked in). NO_PATH + ABSENT gives the combined verdict NOT_REACHABLE, matching truth, where CP2 had abstained with CANT_DETERMINE / ANALYSIS_FAILED.
- `generic_call` (R1 FALSE_NOT_REACHABLE; R2 AGREE; R3 AGREE; R4 REACHABLE): R1 misses the call: `viaGeneric[string]` is passed to `apply` as a function value and called there. VTA follows the value and reports a DYNAMIC edge `apply[string] -> viaGeneric[string]`.
- `unsafe_func_pointer` (R1 FALSE_NOT_REACHABLE; R2 AGREE; R3 FALSE_NOT_REACHABLE; R4 CANT_DETERMINE (METHOD_DISAGREEMENT)): VTA reports NO_PATH (a false NOT_REACHABLE for VTA alone): the function value passes through an `unsafe.Pointer` conversion, and VTA does not track types through `unsafe` (documented limit, see reflect_method). The linker keeps `Parse` because its value is taken. So, contrary to the CP1 note, this case does exercise `unsafe` — for call-graph methods, not for the linker. The combined verdict is CANT_DETERMINE / METHOD_DISAGREEMENT, not a false NOT_REACHABLE.
- `present_but_unreachable` (R1 FALSE_REACHABLE; R2 FALSE_REACHABLE; R3 AGREE; R4 CANT_DETERMINE (METHOD_DISAGREEMENT)): The case CP1's review asked for. The linker keeps `loud.Run`, and so `Parse`: `loud` is converted to an interface (stored in `any`), and a method with the same name and signature is called from a reachable interface call site (`r.Run`), which is the linker's rule for keeping methods of types used in interfaces (`ifaceMethod` / `markableMethods` in cmd/link/internal/ld/deadcode.go). VTA sees that only `quiet{}` reaches `r`. NO_PATH + PRESENT gives CANT_DETERMINE / METHOD_DISAGREEMENT. Linker presence alone is a false REACHABLE; R1 is too (name match on `Run`).
- `closure_never_called` (R1 FALSE_REACHABLE; R2 FALSE_REACHABLE; R3 AGREE; R4 CANT_DETERMINE (METHOD_DISAGREEMENT)): The linker keeps `Parse` because the closure that calls it is created and stored, so its code is in the binary even though it never runs. VTA has no edge to the closure, because nothing calls `stored`. CANT_DETERMINE / METHOD_DISAGREEMENT. R1 attributes calls inside function literals to the enclosing function (main), so it is a false REACHABLE.
- `method_expression` (R1 FALSE_NOT_REACHABLE; R2 AGREE; R3 AGREE; R4 REACHABLE): R1 misses the call: the method expression `vulnlib.Impl.Run` is assigned to `f` and called through it. VTA follows it through the thunk `Impl.Run$thunk`.
- `interface_two_impls_one_used` (R1 FALSE_REACHABLE; R2 AGREE; R3 AGREE; R4 NOT_REACHABLE): R1 is a false REACHABLE through the name match on `Run` (it links `r.Run` to `vulnlib.Impl.Run`). The linker drops `Impl.Run`: the type assertion `r.(vulnlib.Impl)` alone did not keep the method (observed; the linker internals for this were not traced). VTA and linker agree on NOT_REACHABLE.

## Other observations (hand-written)

- `generic_target`: VTA supports the generic form: the target `ParseAny[T]` matches the instance `ParseAny[string]` and a path is found. The linker also now answers it (CP3 task 0c): a bare generic function target matches any instantiation's binary symbol by a prefix rule (`pkg.ParseAny[`), since the concrete type vulndb would name is not recoverable from the shape-specific binary symbol. PATH_FOUND + PRESENT gives the combined verdict REACHABLE, where CP2 had abstained with CANT_DETERMINE / ANALYSIS_FAILED.
- `first_construction_devirtualized`: Not a case id. In the first version of `present_but_unreachable` and `interface_two_impls_one_used`, `r` was assigned directly in main (`var r runner = quiet{}`). The compiler devirtualized `r.Run` (`go build -gcflags='-l -m'` printed `devirtualizing r.Run to quiet` / `to echo`), so no interface call reached the linker and it dropped `loud.Run`: linker ABSENT, no disagreement. Both cases now get `r` from a constructor, which keeps the interface call. Truth did not change. The linker result for a present-but-unreachable symbol therefore depends on compiler optimisations, which matters for real applications.
- `synthetic_call_sites`: Not a case id. Edges inside compiler-generated package initialisers (for example `init_imported.init -> initdep.init -> initdep.init#1`) have no source position; the helper reports them with call_site file "" and line 0. The CP7 verifier will need a rule for these edges.
